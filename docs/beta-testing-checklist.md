# Morrow closed-beta QA checklist

Use this checklist on the deployed build and on a fresh browser profile. Record the browser, device size, steps, expected result, actual result, and severity for every issue.

## 1. First visit and navigation
- [ ] Homepage loads without console errors or missing assets.
- [ ] Entering the workspace opens Overview.
- [ ] Every desktop navigation item opens the correct page.
- [ ] Mobile navigation opens, closes, and closes after a page is selected.
- [ ] The skip-to-content link moves focus to the workspace main region.
- [ ] Returning to the website works from the workspace header.

## 2. Learning spaces
- [ ] Open each starter learning space.
- [ ] Create a space with a name and area.
- [ ] Try submitting the creation form with an empty name.
- [ ] Confirm the new space appears in the list and opens.
- [ ] Refresh and confirm topics remain available.
- [ ] Switch between two spaces and confirm each retains its own conversation and mode.

## 3. Study room
- [ ] Send a normal message and a message containing punctuation.
- [ ] Submit whitespace only; a validation message should appear.
- [ ] Confirm the 1,200-character limit is enforced.
- [ ] Press Enter to send and Shift+Enter to add a line break.
- [ ] Use every mode and verify the mode label and response change.
- [ ] Use each suggested prompt.
- [ ] In Quiz mode, submit B, then A and C, and verify feedback.
- [ ] Restart the conversation and confirm the session is reset.
- [ ] Refresh and confirm the conversation and selected mode persist.
- [ ] Confirm the conversation remains usable on a narrow mobile viewport.

## 4. Study plan and progress
- [ ] Toggle a planned session complete and incomplete.
- [ ] Confirm the weekly completion count and bar update.
- [ ] Refresh and confirm plan changes persist.
- [ ] Confirm a correct quiz answer adds one concept, while ordinary messages and incorrect answers do not.
- [ ] Confirm sending messages does not arbitrarily increase the progress percentage.

## 5. Materials and settings
- [ ] Search materials by full and partial title.
- [ ] Search for a term with no matches and verify the empty state.
- [ ] Confirm sample materials are not mistaken for uploaded personal files.
- [ ] Check whether the display-name field implies a save action; do not treat it as persistent until save behaviour exists.

## 6. Accessibility and responsive checks
- [ ] Complete the main flows using keyboard only.
- [ ] Check visible focus on links, buttons, inputs, and navigation.
- [ ] Confirm dialogs can be opened, completed, and dismissed.
- [ ] Check text contrast and zoom at 200%.
- [ ] Test at approximately 375px, 768px, 1,024px, and desktop width.
- [ ] Check for horizontal overflow and clipped controls.

## Known beta boundaries
- Study responses are scripted, not generated by an AI model.
- Materials are sample cards; upload and document extraction are not implemented.
- Learning spaces and sessions persist in the current browser only. There is no account, server-side storage, or cross-device sync.
- The progress percentage is seeded starter data and is not yet a validated measure of mastery. Concept counts increase only for a correctly selected quiz answer.
- The study plan is a manually toggled checklist, not a calendar integration.

## Release decision
Do not invite external testers until all critical flows above pass on desktop and mobile, the production build and lint checks pass, and the known boundaries are visible to testers. Track visual polish and feature requests separately from defects that block a core flow.
